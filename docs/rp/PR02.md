# PR02 — Mise à jour Android depuis l'application

> **Statut :** À développer · **Dépendance :** PR01 · **Dépôt :** `Hyarius/Domolia`

## Résultat visible dans l'application

L'utilisateur découvre une nouvelle préversion, la télécharge dans Domolia et peut lancer son installation sans visiter GitHub manuellement.

## Périmètre de la PR

- Écran/version courante et canal de mise à jour (`dev-latest` par défaut, préversion de branche pour les tests).
- Consultation des métadonnées GitHub Releases, comparaison fiable des numéros de build Android et indication « à jour » / « disponible ».
- Téléchargement de l'APK avec progression, annulation, état d'erreur, vérification du fichier et invocation de l'installateur Android via intégration native.
- Vérification optionnelle au démarrage, sans installation silencieuse ni notification intrusive.

## Contraintes d'architecture et règles métier

- Ne jamais remplacer l'installateur Android ni contourner sa confirmation ou les autorisations d'installation depuis une source externe.
- Conserver identifiant Android et signature ; gérer réseau absent, lien expiré, téléchargements interrompus et API GitHub indisponible.

## Critères d'acceptation et tests

- Une version N installée détecte N+1 sur GitHub et propose de télécharger l'APK.
- L'utilisateur installe N+1 sur N, sans perdre la configuration ni les données locales.
- Si aucun APK compatible n'est disponible, le bouton affiche une explication et n'ouvre pas de lien mort.

Les tests unitaires et widgets doivent couvrir les règles ajoutées. Tout scénario nécessitant un fournisseur distant doit aussi avoir un test avec une réponse simulée. Si une modification concerne Android, elle doit être vérifiée dans l'APK de préversion de la branche.

## Hors périmètre

Pas de service Android résidant en arrière-plan ; pas d'auto-installation silencieuse.

## Règle de livraison

Cette PR doit être isolée sur une branche de travail, avoir sa CI verte et fournir une évolution testable sur Android. **Ne jamais fusionner sans autorisation explicite du propriétaire.** Le numéro `PR02` est le numéro logique de feuille de route, indépendant du numéro de Pull Request attribué automatiquement par GitHub.
