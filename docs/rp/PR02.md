# PR02 — Mise à jour automatique Android au démarrage

> Statut : implémentation en cours de validation CI et téléphone · Dépendance : PR01.

## Décision produit

Domolia vérifie automatiquement le canal configuré **après le premier affichage**, puis télécharge sans confirmation préalable un APK avec un `versionCode` strictement supérieur. La progression est discrète et annulable, la navigation reste accessible. Une fois l'APK contrôlé, Domolia ouvre directement l'installateur Android ; **l'utilisateur doit toujours accepter les éventuelles permissions et l'installation système**. Aucune installation silencieuse ni processus résident.

Les paramètres exposent la version courante, le canal, la date et l'état de la dernière vérification, l'interrupteur de vérification au lancement (activé par défaut), l'annulation du téléchargement et « Vérifier maintenant ». Les boutons « Mise à jour » de l'accueil et du menu utilisent le même contrôleur.

## Fichiers et architecture

- `lib/updates/update_service.dart` : contrats injectables, machine à états observable, comparateur de build, sérialisation contrôlée des vérifications, annulation et prévention de réouverture de l'installateur pour le même build pendant un démarrage.
- `lib/updates/update_io.dart` : métadonnées GitHub Releases API, téléchargement HTTPS privé, contrôle SHA-256 incrémental, nettoyage des fichiers .part, préférences et canal Flutter/Kotlin.
- `lib/updates/update_widgets.dart` : bande de progression et réglages vert forêt/or.
- `tool/android/MainActivity.kt` : compare nom du paquet, version Android réelle et certificats des APK avant de créer un URI FileProvider. En cas de permission manquante, ouvre les réglages « installation depuis cette application ».
- `tool/configure_android_updates.py` : réapplique le manifeste, la classe Kotlin, FileProvider et AndroidX après chaque `flutter create`. Ce script est également exécuté en CI.
- `tool/generate_update_metadata.py` : inspecte le véritable APK compilé via `aapt`, contrôle son `versionCode` et identifiant de package et produit `Domolia-update.json`.

## Versions, distribution et sécurité

La CI utilise `github.run_number` comme numéro de build monotone par workflow. Chaque release signée distribue son APK et `Domolia-update.json` avec les champs `versionName`, `versionCode`, `channel`, `apkName`, `sha256`, `applicationId`. `main` distribue `dev-latest` + `Domolia-dev.apk` ; les branches publient `preview-<slug>-<hash>` + `Domolia-preview.apk` ; `v*` distribue `Domolia.apk`.

Le client n'accepte qu'un tag `dev-latest` ou `preview-...`, compare les vrais `versionCode` installés, exige le même paquet `fr.domolia.domolia`, puis contrôle le SHA-256 de l'APK reçu. Le pont Android revérifie paquet, version strictement supérieure et certificat de signature. Un appareil sur une préversion ayant un build supérieur à `dev-latest` ne proposera pas d'installation impossible depuis `main` avant rattrapage du compteur.

L'APK est enregistré sous `files/updates/`, exposé uniquement par le FileProvider privé. L'installation utilise `REQUEST_INSTALL_PACKAGES` sur Android 8+, sans permission de stockage. Tous les APK publiés exigent les secrets de signature Android permanente, sinon le build échoue. Une release historique sans JSON n'est pas candidate. SHA-256 seul ne constitue pas une signature d'éditeur : la signature Android est vérifiée séparément.

## Tests automatiques

`test/update_service_test.dart` : aucun nouveau build, téléchargement automatique N+1, progression, annulation, erreurs, SHA-256 refusé (téléchargeur simulé), version identique/ancienne, panne GitHub, option désactivée, autorisation reportée, requêtes concurrentes, canal preview et package invalide. `test/widget_test.dart` : identité visuelle, navigation paramètres, progrès non bloquant et option automatique. Toutes les sources de données sont simulées, sans accès GitHub réel.

La CI doit réussir `flutter analyze`, `flutter test`, build Android/Kotlin, génération de métadonnées via `aapt` et contrôle de certificat avec `apksigner`.

## Procédure N → N+1 sur téléphone (non exécutée ici)

1. Installer une version signée **N contenant PR02** sur le téléphone. Relever le `versionCode` et noter une donnée locale à conserver. Les installations antérieures à PR02 nécessitent une dernière installation manuelle.
2. Sélectionner son canal de préversion dans Paramètres si nécessaire. Pousser une petite modification sur ce canal ; attendre la publication CI de **N+1**, signée avec la même clé et ayant un `versionCode` supérieur.
3. Ouvrir N : vérifier que l'écran principal est immédiatement utilisable, le téléchargement commence, sa progression apparaît et la navigation fonctionne.
4. Quand l'installateur Android apparaît, autoriser l'installation depuis Domolia si le système le demande, puis au besoin relancer « Vérifier maintenant ». Accepter la confirmation **Android**.
5. Rouvrir Domolia, contrôler le numéro N+1 et les données locales conservées, puis vérifier qu'aucune nouvelle installation n'est proposée pour la même version.
6. Refaire un essai avec une connexion interrompue, une annulation, et une préversion dont le build dépasse celui de `main`.

La CI seule ne prouve pas ce scénario réel. Aucun résultat sur téléphone ne doit être revendiqué sans avoir effectivement testé deux APK sur le même appareil.
