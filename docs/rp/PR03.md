# PR03 — Connexion sécurisée à OpenUncensored

> **Statut :** Implémentée sur branche de travail — en validation · **Dépendance :** PR02 · **Dépôt :** `Hyarius/Domolia`

## Résultat visible dans l'application

Depuis les paramètres, l'utilisateur configure sa clé OpenUncensored, sélectionne un modèle et vérifie que la connexion fonctionne.

## Périmètre de la PR

- Écran « Fournisseur IA » en français : base URL initiale `https://api.openuncensored.com/v1`, clé API masquée, modèle de chat paramétrable et test de connexion.
- Transport HTTP OpenAI-compatible dédié aux réponses chat, gestion propre des timeouts, erreurs HTTP et limites de débit.
- Stockage des secrets via mécanisme sécurisé Android (pas en SQLite texte, logs, crash reports ni dépôt).
- Interfaces internes séparant les fournisseurs du domaine RP pour éviter de figer toutes les fonctionnalités dans un fournisseur.

## Contraintes d'architecture et règles métier

- L'application tourne sur le téléphone ; seule l'inférence est distante et consomme des crédits du fournisseur.
- Ne jamais journaliser Authorization, prompts sensibles ou réponses brutes par défaut ; messages d'erreur non divulgateurs.

## Critères d'acceptation et tests

- Une clé valide permet de récupérer une courte réponse d'essai en français.
- Sans clé ou hors ligne, l'écran affiche une erreur compréhensible, sans crash.
- Le redémarrage de l'application conserve la configuration chiffrée ; les tests utilisent un serveur simulé.

Les tests unitaires et widgets doivent couvrir les règles ajoutées. Tout scénario nécessitant un fournisseur distant doit aussi avoir un test avec une réponse simulée. Si une modification concerne Android, elle doit être vérifiée dans l'APK de préversion de la branche.

## Hors périmètre

Pas encore de moteur RP ni de persistance des aventures.

## Règle de livraison

Cette PR doit être isolée sur une branche de travail, avoir sa CI verte et fournir une évolution testable sur Android. **Ne jamais fusionner sans autorisation explicite du propriétaire.** Le numéro `PR03` est le numéro logique de feuille de route, indépendant du numéro de Pull Request attribué automatiquement par GitHub.

## Implémentation et essai sur Android

1. Installer l'APK de préversion PR03 (même signature que PR02).
2. Ouvrir **Menu → Paramètres → Fournisseur IA**.
3. Conserver l'URL HTTPS `https://api.openuncensored.com/v1`, saisir une clé API `ou-…`, puis **Enregistrer la configuration**.
4. Cliquer **Charger les modèles** pour obtenir les identifiants actuellement proposés par `GET /v1/models`. Les modèles textuels disponibles sont filtrés. Choisir le modèle dans le menu déroulant, sans champ de saisie libre.
5. Cliquer **Tester la connexion**. Cette action enregistre les champs puis envoie une courte requête `POST /v1/chat/completions` en français. Le fournisseur peut décompter des crédits.
6. Fermer et rouvrir Domolia : l'URL, le modèle et la présence de la clé doivent être conservés. Le champ secret reste vide et masqué ; saisir une nouvelle clé la remplace, laisser vide conserve l'ancienne, « Supprimer la clé API » la retire.
7. Vérifier les erreurs : sans clé, réseau coupé, mauvaise clé (401/403), crédits épuisés (402), limite 429, modèle invalide (404). Elles doivent être lisibles, sans afficher de clé ou de réponse brute d'erreur.

### Sécurité et architecture

- `AiChatProvider` est l'interface générique chat (modèles et complétion), indépendante des écrans ou du RP. `OpenAiCompatibleChatProvider` implémente seulement le protocole réseau OpenAI-compatible.
- `AiConfigurationStore` isole le stockage. La configuration est conservée intégralement dans `flutter_secure_storage` 10.x, qui chiffre les valeurs sur Android avec AES-GCM et une clé protégée par Android Keystore.
- Le fichier de manifeste généré désactive la sauvegarde Android automatique et le transfert d'application via les règles `dataExtractionRules` : restaurer des valeurs chiffrées sans la clé Keystore originale est dangereux. Une sauvegarde/export des aventures sera traitée par PR17.
- L'URL doit être HTTPS ; aucun redirect HTTP n'est suivi ; aucune réponse d'erreur brute ou exception de transport n'est affichée. Aucun secret n'est injecté dans les `dart-defines`, les logs ou la CI.
- Les réponses de tests sont affichées uniquement à la demande (320 caractères maximum). Pas d'inférence ni de facturation automatique au démarrage.
- Tests : réponses HTTP simulées, formats JSON invalides, catalogue, rejets HTTP, URL non TLS, absence de clé, échec hors ligne, conservation des préférences et scénario Widget. La CI teste puis construit l'APK de branche ; le test avec une vraie clé reste manuel.
- API officielle : https://openuncensored.com/docs

## Ajustements de l'interface pendant la revue

- Le choix de modèle se fait uniquement avec **Modèle de chat**, un menu déroulant permanent. Le champ de saisie libre est supprimé. Le modèle déjà enregistré est visible avant même le chargement du catalogue ; **Charger les modèles** actualise les options.
- Chaque vérification **manuelle** des mises à jour (accueil, barre supérieure, menu ou paramètres) ouvre une fenêtre indiquant la recherche, la progression, l'absence de mise à jour, la demande d'installation ou une erreur. La vérification automatique au démarrage reste discrète.
