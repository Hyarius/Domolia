# PR14 — Extraction visuelle fidèle des scènes RP

> **Statut :** À développer · **Dépendance :** PR13 · **Dépôt :** `Hyarius/Domolia`

## Résultat visible dans l'application

Un bouton « Illustrer cette scène » prépare une description factuelle de l'instant final de la narration, avant toute génération d'image.

## Périmètre de la PR

- Étape indépendante `Story Facts` sur le dernier échange joueur/narrateur, utilisant un modèle configuré pour extraction structurée.
- Schéma JSON validé : lieu, lumière constatée, instant final, objets, personnages présents, actions, positions, regard, vêtements temporaires et limites du joueur.
- Prévisualisation/correction du JSON en interface, possibilité de désactiver ou relancer l'extraction.
- Tests réalistes : quatre personnages au même endroit ; départ d'Aoi ; manteau hivernal de Ren ; scène adulte entre majeurs selon préférences ; environnement vide.

## Contraintes d'architecture et règles métier

- Sélectionner strictement le dernier instant représentable ; ne pas combiner deux étapes temporelles successives.
- Ne jamais réintroduire une personne partie ni inventer une action pour le personnage joueur.
- Aucun prompt d'image ou style graphique dans les données factuelles ; `null` JSON réel pour les inconnus.

## Critères d'acceptation et tests

- La scène de réparation après le départ d'Aoi contient Ren et Hana, pas Aoi.
- Le vêtement d'hiver est conservé et la tenue habituelle n'est pas rétablie par erreur.
- Chaque réponse est un JSON conforme ou un échec affiché sans données corrompues.

Les tests unitaires et widgets doivent couvrir les règles ajoutées. Tout scénario nécessitant un fournisseur distant doit aussi avoir un test avec une réponse simulée. Si une modification concerne Android, elle doit être vérifiée dans l'APK de préversion de la branche.

## Hors périmètre

Cette PR ne lance pas encore de génération d'image ; elle garantit seulement la fidélité des faits.

## Règle de livraison

Cette PR doit être isolée sur une branche de travail, avoir sa CI verte et fournir une évolution testable sur Android. **Ne jamais fusionner sans autorisation explicite du propriétaire.** Le numéro `PR14` est le numéro logique de feuille de route, indépendant du numéro de Pull Request attribué automatiquement par GitHub.
