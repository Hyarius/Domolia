# PR06 — CI, publication GitHub Pages et versions

## Périmètre

- Ajouter workflow GitHub Actions Web indépendant de `android-apk.yml`, déclenché sur PR pour analyser, tester, assembler et vérifier ressources.
- Générer/valider `web/`, publier SQLite WASM + worker, compiler sous `/Domolia/` (ex. `flutter build web --base-href /Domolia/`).
- Déployer via GitHub Pages **seulement après fusion sur la branche approuvée**, en permissions minimales (`contents: read`, `pages: write`, `id-token: write`) et réglage GitHub Pages : source GitHub Actions.
- Vérifier l'application à `https://hyarius.github.io/Domolia/`, l'initialisation WASM, les ressources, rechargement et migration après nouvelle version.
- Utiliser stratégie de cache adaptée au Flutter courant : ne pas supposer le service worker Flutter historique ; envisager `--web-content-hash` si SDK compatible et contrôler l'entrée non mise en cache indéfiniment.
- Documenter fonctionnement local, navigation privée, effacement des données, absence de sync, sauvegardes et fournisseurs IA réellement compatibles.

## Acceptation

- CI Web et CI Android vertes, pas de publication officielle de branche PR.
- Tests fonctionnels GitHub Pages sur Firefox/Chrome/Edge, conservation des données après déploiement d'une nouvelle version.
- Fichier de sauvegarde utilisable sur autre navigateur/Android ; aucune donnée envoyée à GitHub Pages.
- Pas de fusion sans accord.
